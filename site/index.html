Team chat that runs
from a single binary.

rslack is self-hosted, Slack-style chat. Channels, DMs, threads, reactions, search and uploads in one ~7 MB executable and one SQLite file. No Postgres, no Redis, no Node.

Everything a small team needs.

Every feature below was exercised in a real two-user browser run. The screenshots on this page come from that run.

Realtime
WebSocket fan-out for new, edited and deleted messages, reactions, thread replies, typing and presence.
Channels & DMs
Public and invite-only private channels, plus 1:1 direct messages. Private channels stay invisible to outsiders.
Threads
Reply to any message in a side panel. Parents show the reply count and when the last reply came in.
Reactions
One-click emoji reactions that toggle per user and sync instantly to everyone in the channel.
Full-text search
SQLite FTS5 with prefix matching. Results only include channels you can read; input is quoted, so search syntax can't be injected.
Unreads & mentions
Per-channel unread and mention badges, a "New" marker at your first unread, and @mention autocomplete.
Uploads
Drag, drop or paste files. Images render inline, downloads are access-checked, and there's a size limit.
Sane auth
argon2id passwords, hashed session tokens in HttpOnly cookies, and WebSocket origin checks.
Light & dark
Follows your OS and can be toggled. Plain HTML, CSS and JS embedded in the binary, with no build step.

Quickstart

Build it, run it, open the browser. Create an account and a workspace, then share the invite code.

# from source
git clone https://github.com/shubhxho/rslack
cd rslack
cargo build --release
./target/release/rslack
# → http://127.0.0.1:8080, data in ./data
RSLACK_HOSTbind address, 127.0.0.1
RSLACK_PORTport, 8080
RSLACK_DATA_DIRSQLite + uploads, ./data
RSLACK_MAX_UPLOAD_MBper-file limit, 10
RSLACK_SECURE_COOKIEStrue behind HTTPS
RSLACK_ALLOW_SIGNUPfalse to close sign-ups
RSLACK_PUBLIC_ORIGINpublic URL when a proxy rewrites Host

Every option is also a CLI flag, e.g. rslack --port 9000 --data-dir /srv/rslack.

Docker

A two-stage Dockerfile ending in a non-root Debian slim image, plus a documented docker-compose.yml.

docker compose up -d
# → http://localhost:8080 · data persists in the rslack-data volume

How it works

A REST handler checks access, commits to SQLite, then hands a JSON event to an in-process hub that pushes it to every open socket of the channel's members. Nothing reaches a client before it's persisted; a client that reconnects simply re-fetches.
